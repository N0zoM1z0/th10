## Useful control-flow leads

The reference C++ model keeps opcode, portrait-stage, name-stage and stage-six
difficulty switches lexically in one dispatcher. Their **24/7/7/5** selector
domains independently agree with our target decode. Its top-tested walker,
distinct END and pending-WAIT exits, live-command advance, final tick, character
0/1 guards and stage-seven variant split provide useful questions for a future
ordinary whole-owner source model. They do not establish compiler emission.
See the pinned [dispatcher and nested switches](https://github.com/levzzz5154/th10-decomp/blob/eb027539e55372735db1d60ae5da781a9d1caa8a/matching2/msvc/build_support/contexts/equivalent/game/front_script_tick.cpp#L72-L442).

## Context that must not transfer

The reference uses forced-inline helpers/macros, a custom implementation-file
cluster, noinline interfaces, address-named sections and an address-returning
escape function to influence global reloads. Its layout supplies absolute
code/global bindings and roots the escape function; hiding helper bodies also
changes compiler visibility. These mechanisms and unverified upstream scores
are not part of our ordinary fixed dependency graph. See the pinned
[unit context](https://github.com/levzzz5154/th10-decomp/blob/eb027539e55372735db1d60ae5da781a9d1caa8a/matching2/msvc/src/game/front/front_script_tick_unit.cpp)
and [layout/bindings](https://github.com/levzzz5154/th10-decomp/blob/eb027539e55372735db1d60ae5da781a9d1caa8a/matching2/msvc/build_support/layout/equivalent/front_script_tick.json).

That layout declares a **4308-byte comparison extent**. This is a configuration
observation, not a validated generated length. Our standard remains the complete
**4480-byte** target owner: 4306 executable bytes, two alignment bytes and all
172 selector bytes. No reference PE/PDB, generated tables or relocation proof
was independently validated.

Reference packed operand views, reinterpretation of byte storage and bitfield
overlays do not resolve our lifetime, extent or alias obligations. Its shared
text helper rereads the manager global after decoding, despite a cached-manager
comment. Our target distinguishes cached paths from opcode16's zero-branch
reload; that distinction must survive source review. Source declarations alone
also cannot guarantee stack/RET4 under LTCG. See the pinned
[helper mechanisms](https://github.com/levzzz5154/th10-decomp/blob/eb027539e55372735db1d60ae5da781a9d1caa8a/matching2/msvc/build_support/contexts/equivalent/game/front_script_tick.cpp#L3-L70).

## Disposition

The current candidate remains non-exact: a 1244-byte Run owner, separate static
helpers and lookup arrays, with the caller ABI and unresolved dependency limits
recorded in [the native baseline](GUI_MESSAGE_RUN_NATIVE_BASELINE.md). No helper
bytes are summed into owner credit. After recovering missing real dependencies,
a principled next investigation is ordinary lexical switches independently
derived from our target, preserving byte-safe storage and live-read distinctions.
Any native evaluation must retain the complete-owner/table, actual-caller and
fixed-graph review gates. This reference comparison changes no acceptance or
exactness classification.
