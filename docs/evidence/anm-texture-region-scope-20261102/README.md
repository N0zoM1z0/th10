## Recovered source and object lifetimes

The previous maintained implementation placed a surface description and three
independent rectangles at function scope and initialized the local surface to
null at declaration. Under the selected real AsciiManagerView::Initialize
LTCG entry this produced the older 321-byte implementation with the wrong
0x54 stack frame. The target uses a 0x34 frame that permits the file
description/destination rectangle and the embedded-data source/destination
rectangles to occupy **branch-exclusive** local storage.

The current implementation declares each pair in its consuming branch and
publishes surface = NULL immediately before GetSurfaceLevel. This
preserves the allocation/read/upload/release paths and the originally
unread incoming argument. The target and candidate now agree through
offset +0xA1 with the first three independently located address fields
normalised. At +0xA2 the target's local branch displacement is one
greater because the later embedded-texture header address calculation is one
byte longer in the target. The native PDB reports a 319-byte whole owner,
so no 320-byte byte comparison is represented as exact.

The target's embedded branch begins with MOV ECX,[EDI+0x30] then
LEA EAX,[ECX+EDI]. The native version emits MOV EAX,[EDI+0x30]
then ADD EAX,EDI. The target MOV+LEA is eight bytes; native MOV+ADD is
seven. Subsequent instructions use different ECX/EDX temporaries until the
blocks rejoin. This is a real codegen frontier, not an address-field waiver.
