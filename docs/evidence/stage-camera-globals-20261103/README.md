## Original PE evidence

Direct original executable disassembly (and independent hash-attested
read-only Ghidra) establishes **two adjacent 0x118-byte** state blocks:

- Published stage camera: **0x00491D7C**, independently named and consumed
  by existing `StageScript`, `StageDraw`, `StageLifecycle` code.
- Secondary default camera: **0x00491E94** (`0x00491D7C + 0x118`).
  The target startup initializes the secondary object's fields first.

Both objects receive position `(0,0,1000)`, direction `(0,0,0)`, up
`(0,1,0)`, rocking offset `(0,0,0)` and `value048=0.5235988f`
(exact binary32 word `0x3F060A92`). The secondary viewport is `(0,0,640,480,
0,1)` and the published viewport is `(32,16,384,448,0,1)`.
The target only initializes these particular fields; it does not clear or
rebuild the matrices, tangent vectors, fog, or unrelated aggregate storage.
The physical data/source-translation-unit ownership remains unproven.

## Native compiler controls and exactness boundary

An initial pinned VC7.1 SP1 `/GL` single-source link of the actual typed
implementation emitted a **537-byte** PDB-owned function for the 465-byte
native target. Reordering the independent published rocking-offset stores
after viewport setup, and selecting the secondary viewport before the
published default FOV, improved this to **518 vs 465** (48/333 preliminary
ordinary comparable bytes; 38 candidate link fields, not independently
bound). The compiler's global-store interleaving, which merges many vector
stack temporary uses in the original, remains different. The first version
is archived privately at
`.analysis/gpt-web/20261103/stage-camera-defaults/initial.cpp`.

This is source coverage with an explicit complete function boundary,
**NONEXACT**, no match-unit or exact-ledger admission. There is no claim
about runtime/product equivalence, original identifiers or raw percentage.
