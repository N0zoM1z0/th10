# ANM loaded sprite and script indices: original low-16-bit publication

Original target: Japanese TH10 1.00a, SHA-256 2f14760b6fbbf57549541583283badb9a19a4222b90f0a146d5aa17f01dc9040.

Three authored ANM paths store script-controlled 32-bit index values in signed 16-bit VM fields: SetSprite stores activeSpriteIndex, while SetAndExecuteScriptIndex and SetAndExecuteScriptIdx each store scriptIndex. The retail i386 instructions write the low 16 bits even when the input is outside the signed short range. The prior source cast an int to short, an implementation-defined conversion for values outside [-32768,32767]. The new source stores the low unsigned short through the corresponding unsigned type of the existing short field. This is ordinary C++ signed/unsigned counterpart aliasing and preserves the original low-word machine behavior, rather than clamping invalid script input or changing the object layout.

Six genuine VC7.1 SP1 /GL source variants under the real ANM executor entry compared baseline, each of the three sites individually, script-index sites together, and all three. In every trial the complete existing exact 356-byte SetSprite owner remained 348/348 ordinary bytes plus both original constant fields; the exact 194-byte SetAndExecuteScriptIndex remained 182/182 ordinary bytes plus all three original fields. The nonexact 287-byte SetAndExecuteScriptIdx retained its full size, 249/271 ordinary bytes and four original fields, with the same ESI/EDI register-selection differences.
